# Space Dodger — правила помощника

## Назначение

Это стартовое состояние темы 1 практикума. Реализуй только текущий согласованный
шаг ученика. Сначала предложи план сцен, состояний и проверок; дождись согласования
перед реализацией игрового шага. Не переноси готовую игру или её ассеты.

## Стек и структура

- Godot 4.7.2, 2D, GDScript со статической типизацией и явными типами возврата.
- Базовое поле 1920×1080, окно 1280×720, stretch `canvas_items`, фильтр Nearest.
- `scenes/` — сцены; `scripts/` — код; `assets/sprites/`, `assets/audio/`,
  `assets/fonts/` — свои или лицензированные материалы. Регистр путей важен.
- Сырьё держи в `_raw/` с `.gdignore`, отдельно от готовых спрайтов.
- `data/obstacles.json` — шаблон каталога с одной выключенной записью.
  Заполняй его вместе с учеником на соответствующем шаге, сохраняй формат.
- `tests/` — проверки на встроенном `SceneTree`; сторонний тестовый фреймворк не нужен.
- `addons/godot_ai/` — сторонний MCP-мост 4.3.0 под MIT; сохраняй его лицензию.

## Работа над кодом

- Один скрипт — одна задача. Параметры сложности собирай в одном месте.
- Используй действия Input Map из `project.godot`, без кодов клавиш в игровом коде:
  `move_*`, `shoot`, `dash`, `pause`, `restart`.
- Движение учитывает `delta`; проверки столкновений ждут физических кадров.
- Ссылки на узлы сохраняй через `@onready`; избегай поиска узлов и создания объектов
  в `_process` без необходимости.
- Перед изменением сцены через MCP останови игру (`project_manage`, действие `stop`).
- Работай внутри этого проекта. Новую большую задачу начинай с чтения правил,
  плана и последних записей в `ЖУРНАЛ.md` и `ИИ-ЖУРНАЛ.md`, когда они появятся.

## Ограничения

- Не редактируй `.godot/` и `*.import` вручную.
- Не удаляй сцены, не добавляй и не обновляй аддоны без согласования с учеником.
- Не удаляй и не ослабляй проверки ради успешного результата.
- Не записывай учётные данные в код, чат, репозиторий или клиентскую сборку.
  Для необязательных внешних инструментов используй окружение вне проекта.
- MCP подключай только локально, в scope `project`, с выключенной телеметрией.
- Не создавай историю Git и не делай коммиты без запроса ученика.

## Проверка шага

- Проект открывается и запускается по F5 без ошибок и предупреждений.
- `godot --headless --path . -s tests/smoke_test.gd` проходит. Сейчас это только
  проверка загрузки пустой сцены; дополняй проверки по мере реализации механик.
- Кадр просмотрен человеком; автотест не доказывает качество графики или плейтест.
- Проверки не перезаписывают пользовательские сохранения, если они появятся.
- В журналах разделены изменения помощника, решения ученика и проверенные факты.
  Непроведённые проверки указаны явно.
